# 27장 영상 생성, 테이크 비교, 재생성

<ChapterGoals />

## WHY

> 같은 프롬프트로 다시 만들었는데 왜 결과가 다를까요? 그리고 여러 결과 중 무엇을 남겨야 할까요?

- 씬 하나를 영상으로 생성하고, 진행 단계 문구를 읽을 수 있습니다.
- 테이크(T1, T2 …)를 **생성 정보**와 **대비 바뀐 점**으로 비교할 수 있습니다.
- 아쉬운 점을 한 가지씩 고쳐 재생성하는 습관을 익힙니다.

**완성 결과물** 「비 오는 정류장」 씬 1의 테이크 2개 이상과, 그중 고른 테이크 1개 (결과 27-A)

## HOW

### 생성은 '뽑기'가 아니라 '실험'입니다

생성형 영상 모델은 같은 입력에도 매번 조금씩 다른 결과를 냅니다(3장의 '잡음에서 시작하는 생성' 참고). 그래서 한 번에 완성본을 얻으려 하기보다, **조건을 하나씩 바꾸며 테이크를 쌓고 비교**하는 것이 실전 방법입니다. 영화 촬영장에서 같은 장면을 여러 번 찍는 '테이크'와 같은 개념입니다. FECINE의 작품 구조는 **에피소드 > 씬 > 샷 > 테이크**이고, 영상은 씬 단위로 생성되어 테이크로 쌓입니다.

| 개념 | 뜻 | FECINE에서 |
| --- | --- | --- |
| 테이크 | 한 씬을 생성한 결과 한 개 | 씬마다 T1, T2 … 로 쌓임 (`테이크 {count}`) |
| 생성 정보 | 그 테이크를 만든 모델·프롬프트·참조 | 테이크의 **생성 정보** 창 |
| 변수 통제 | 한 번에 하나만 바꾸기 | **대비 바뀐 점**이 바뀐 항목을 알려 줌 |
| 재생성 | 고친 조건으로 다시 생성 | **생성** / 실패 시 **재시도** |

### 진행 단계 읽기

**생성**을 누르면 상태 문구가 다음 순서로 바뀝니다. 어디서 멈췄는지 알면 원인을 짐작할 수 있습니다.

| 문구 | 의미 |
| --- | --- |
| 에셋 그룹 준비 중… | 씬에 연결된 자료를 모으는 중 |
| 참조 이미지 준비 중… | 등장인물·배경·소품·샷 이미지를 모델에 보낼 준비 |
| 렌더링 대기열에 추가 중… | 영상을 만드는 외부 AI 회사(제공자)에 요청을 보내는 중. 이때부터 크레딧이 듭니다. 같은 모델의 앞선 요청이 있으면 그 요청이 끝난 뒤 바로 시작한다고 안내합니다 |
| 영상 렌더링 중… | 모델이 영상을 만드는 중. **예상 시간 약 …**이 함께 표시됨 |
| 영상 저장 중… | 완성된 영상을 작품에 저장하는 중 |

### FECINE에서 하기

1. 작품 왼쪽 `제작 모듈` 메뉴에서 **스토리보드**를 열고 씬 1을 고릅니다. `모델` 탭의 **씬 영상 생성** 영역을 봅니다.
2. **모델**, **길이**, **해상도**를 고릅니다. 이 책의 예제는 해상도 720p(16장에서 작품을 만들 때 정한 값), 씬당 5초를 기준으로 합니다. 해상도는 화면의 선명함입니다. 모델이 작품 비율을 지원하지 않으면 어떤 비율로 만들어지는지 미리 안내가 나옵니다.
3. 참조로 쓸 이미지를 확인합니다. 새 영상을 만들 때 작품의 등장인물·배경·소품 이미지를 참조 이미지로 고를 수 있고, 프롬프트에 `@`로 넣지 않은 참조는 영상에 쓰이지 않는다고 표시됩니다. 프롬프트 글자 수 표시가 모델 한도 안인지도 봅니다.
4. 같은 장소·시간에서 바로 이어지는 씬이라면 시작 이미지 칸의 **앞 씬과 이어짐**을 켭니다. 영상 프롬프트가 앞 영상이 끝난 순간에서 시작하고, 편집에서 첫 0.2초를 자동으로 잘라 둡니다. 앞 씬 영상의 끝 장면을 첫 프레임으로 쓰려면 **앞 씬 끝 장면으로 시작**을 누릅니다. 씬 1은 첫 씬이므로 해당하지 않습니다.
5. **생성**을 누르고 진행 단계 문구를 확인합니다. 결과가 나오면 테이크 **T1**이 생깁니다.
6. T1을 재생한 뒤 **이 테이크 어땠나요?**에서 **좋아요** 또는 **아쉬워요**를 누릅니다. **아쉬워요**를 고르면 이유(스타일이 다름 / 얼굴·의상이 바뀜 / 움직임이 어색함 / 카메라가 지시와 다름 / 글자·워터마크 / 소리)를 고를 수 있고, 이유마다 고칠 탭을 안내하는 팁이 나옵니다.
7. 팁이 안내한 탭(**씬**, **프롬프트**, **카메라**, **스타일**, **모델**)에서 **한 가지만** 고치고 다시 **생성**합니다. T2가 생깁니다. 다시 만들 때는 지난번에 쓴 참조 이미지가 그대로 선택돼 있습니다.
8. T2의 **생성 정보**를 열어 **T1 대비 바뀐 점**을 확인합니다. 바뀐 항목이 하나뿐인지 봅니다.
9. 마음에 드는 테이크를 정합니다. 실제로 영상에 쓸 테이크는 28장 편집에서 고릅니다.

::: tip TIP
**대비 바뀐 점**에 `한 번에 n가지가 바뀌었어요`가 보이면 실험이 섞인 것입니다. 무엇이 효과가 있었는지 알 수 없으니, 다음 테이크는 하나만 바꿔 보세요.
:::

::: info NOTE
**프롬프트 보기**를 누르면 **테이크 프롬프트** 창에서 내가 쓴 **프롬프트**와, 스타일·카메라 문장이 합쳐져 모델에 실제로 **전송됨** 본을 나눠 볼 수 있습니다. 결과가 예상과 다르면 전송본부터 읽어 보세요.
:::

::: info NOTE
가지고 있는 영상 파일은 **영상 넣기**에서 **올리기**/**라이브러리**/**영상 디자인** 중 하나로 골라 **테이크로 넣기**를 누르면 새 테이크로 들어갑니다. 생성하지 않으므로 비용이 들지 않습니다.
:::

::: warning 주의
**대기 취소**는 제공자가 요청을 받기 전(또는 접수 여부를 알 수 없을 때)에만 할 수 있습니다. 제공자가 이미 영상을 만들기 시작했다면 중간에 멈출 수 없으므로, 끝날 때까지 기다린 뒤 결과를 보고 다시 만듭니다. 접수 여부를 알 수 없는 요청은 2시간이 지나면 과금 없이 종료됩니다.
:::

## PRACTICE

**실습 27-1 첫 테이크 만들기**

씬 1(비 오는 버스 정류장)을 26장에서 만든 샷 이미지와 함께 생성합니다.

```text
모델: (워크스페이스에서 고를 수 있는 영상 모델 중 하나)
길이: 5초   해상도: 720p
프롬프트: @수아 가 비 오는 버스 정류장 지붕 아래에 서서 젖은 도로를 바라본다.
         빗줄기가 가로등 불빛에 비친다. 카메라는 천천히 다가간다.
```

**실습 27-2 한 가지만 바꿔 재생성하기**

T1을 보고 아래 표에서 가장 아쉬운 항목 **하나**만 골라 고친 뒤 T2를 만듭니다.

| T1에서 아쉬운 점 | 바꿀 곳 | 바꾸는 예 |
| --- | --- | --- |
| 수아의 얼굴·옷이 다름 | 씬 탭 | 등장인물 참조 이미지 연결 확인, 프롬프트에 '어깨 길이의 검은 생머리, 베이지 트렌치코트' 추가 |
| 움직임이 어색함 | 프롬프트 탭 | 동작을 '서서 바라본다' 하나만 남김 |
| 카메라가 지시와 다름 | 카메라 탭 | 시작 → 움직임 → 끝을 '미디엄 → 천천히 다가감 → 클로즈업'으로 지정 |
| 화면에 글자가 생김 | 프롬프트 탭 | 화면에 나올 글자 표현 삭제 |

::: cost COST · 비용

## REVIEW

- [ ] 진행 단계 문구 5개의 의미를 설명할 수 있다.
- [ ] 테이크 2개 이상을 만들고 **생성 정보**를 열어 봤다.
- [ ] **대비 바뀐 점**에 항목이 하나만 표시되도록 재생성했다.
- [ ] **이 테이크 어땠나요?** 평가를 남겼다.
- [ ] 평가표로 남길 테이크를 정했다.

| 상황 | 화면 문구 | 해결 |
| --- | --- | --- |
| 크레딧 부족 | 크레딧이 부족합니다. 충전 후 다시 생성하세요. | **충전하기** 후 다시 생성 (부록 A 참고) |
| 이미 생성 중 | 이 씬의 영상이 이미 생성 중입니다. | 진행 중인 테이크가 끝날 때까지 기다림 |
| 모델이 없음 | 이 워크스페이스에 구성된 영상 모델이 아직 없습니다. | 관리자에게 모델 구성 요청 |
| 프롬프트가 김 | 입력 길이 초과(…자 초과) | 프롬프트를 줄이거나, 스타일 탭에서 룩을 덜 고르거나, 다른 모델 선택 |
| 참조 이미지 없음 | 일부 @ 참조에 아직 이미지가 없습니다 | 이름을 눌러 참조 이미지를 먼저 생성 |
| 참조 1장만 받는 모델 | 이 모델은 이미지를 1장만 받아요. | **샷 이미지 만들기**로 샷 이미지 1장을 준비 (26장) |
| 해상도·길이 불일치 | 선택한 모델이 지원하는 해상도와 길이를 다시 선택해 주세요. | 모델이 지원하는 값으로 다시 선택 |
| 생성 실패 | 생성 실패 | **재시도**. 같은 실패가 반복되면 프롬프트나 모델을 바꿈 |
| 결과가 안 옴 | 영상 렌더링 중…이 오래 지속 | **상태 다시 가져오기** (추가 과금 없음) |
| 차례를 기다림 | 앞선 작업 요청이 끝나면 바로 시작해요. | 그대로 기다림. 같은 모델의 앞선 요청이 끝나면 자동으로 시작 |

**확인 문제**

1. T2의 **대비 바뀐 점**에 '모델 변경'과 '프롬프트 수정'이 함께 보입니다. 이 실험의 문제는 무엇인가요?
2. **상태 다시 가져오기**를 눌러도 비용이 추가로 들지 않는 이유는 무엇인가요?
3. 내가 쓴 프롬프트와 모델에 **전송됨** 프롬프트가 다른 이유는 무엇인가요?

정답: 1. 두 가지가 동시에 바뀌어 어느 쪽이 결과를 바꿨는지 알 수 없다. 2. 이미 제출·과금된 요청의 상태만 다시 확인하기 때문이다. 3. 작품의 스타일·카메라 설정 문장이 자동으로 합쳐져 전송되기 때문이다.

**응용 과제** 씬 2(건네진 우산)를 테이크 3개까지 만들되, 매번 하나씩만 바꾸고 평가표를 채우세요. 마지막 테이크의 **생성 정보** 화면을 캡처해 함께 제출합니다.
