# 텍스트 생성 AI

<ChapterGoals />

## WHY — 영상 제작에 왜 글 쓰는 AI가 필요할까요?

> 영상 AI가 영상을 만드는데, 왜 텍스트 AI까지 알아야 하나요?

AI 영상의 품질은 **글**에서 시작합니다. 장면을 나누고, 원고를 다듬고, 원고를 영상용 프롬프트로 바꾸는 일을 텍스트 생성 AI가 돕습니다. 텍스트 AI가 어떻게 글을 만드는지 알면, 그럴듯하지만 틀린 글을 걸러 내고 더 좋은 요청을 쓸 수 있습니다.

- 텍스트 생성 AI가 글을 만드는 방식과 토큰을 설명한다.
- FECINE에서 텍스트 AI가 쓰이는 다섯 곳을 안다.
- AI가 쓴 글을 확인하고 적용하는 습관을 들인다.

**완성 결과물** 「비 오는 정류장」 텍스트 AI 요청문과 검토표

## HOW — 원리와 FECINE에서 쓰는 곳

### 다음 말을 이어 쓰는 기계

텍스트 생성 AI(대규모 언어 모델, LLM)는 많은 글을 학습해 **앞의 글 다음에 올 말을 확률로 골라 이어 쓰는** 방식으로 동작합니다. 그래서 다음과 같은 성질이 있습니다.

| 성질 | 뜻 | 실습에서 |
| --- | --- | --- |
| 매번 조금씩 다름 | 같은 요청에도 표현이 달라짐 | 마음에 들 때까지 다시 받되, 비교하고 고르기 |
| 그럴듯한 오류 | 사실이 아닌 내용을 자연스럽게 씀(환각) | 설정·이름·순서가 원고와 맞는지 확인 |
| 요청에 민감 | 무엇을, 얼마나, 어떤 말투로 원하는지에 따라 결과가 달라짐 | 목적·분량·톤을 함께 적기 |
| 한 번에 읽는 양의 한도 | 너무 긴 글은 나누어 처리 | 긴 대본은 읽을 범위를 정하기 ([19장](/v1/chapters/19-ai-build)) |

### 토큰과 요금

텍스트 AI는 글을 **토큰**이라는 작은 조각으로 나누어 읽고 씁니다. 요금은 읽은 토큰(입력)과 쓴 토큰(출력)의 양으로 정해지며, FECINE의 요금표에서 텍스트 모델은 **크레딧/100만 토큰** 단위로 표시됩니다([13장](/v1/chapters/13-credits-and-cost), [부록 A](/v1/appendix/a-models-cost)). 같은 작업도 대본이 길수록, 만들 항목이 많을수록 비용이 늘어납니다.

### FECINE에서 텍스트 AI가 쓰이는 곳

| 기능 | 하는 일 | 화면 | 장 |
| --- | --- | --- | --- |
| AI로 장면 나누기 | 회차를 여러 장면으로 나눔(장면 수: 자동 · 4 · 6 · 8개, 바라는 점 입력) | **스토리** | [18](/v1/chapters/18-ai-writing) |
| AI로 쓰기 / AI로 다듬기 | 장면 원고를 쓰거나 고침. 프리셋: 대사 다듬기 · 긴장감 높이기 · 분량 줄이기 · 시작 훅 강화 · 맞춤법·띄어쓰기만 | **스토리** 원고 | 18 |
| AI로 작품 구성 | 대본 파일을 읽어 회차·장면·캐릭터·배경·소품·콘티를 만듦(이미지는 만들지 않음) | **AI 구성** | [19](/v1/chapters/19-ai-build) |
| 원고로 프롬프트 만들기 | 장면 원고를 영상 프롬프트와 권장 길이로 바꿈 | 스토리보드 **프롬프트** 탭 | [25](/v1/chapters/25-camera-style) |
| AI 어시스턴트 | 지금 보는 캐릭터·장면을 맥락으로 프롬프트를 함께 다듬음. 제안만 하고 적용은 직접 누름 | 작품 안 상단 **AI 어시스턴트** | 18·25 |

텍스트 모델은 워크스페이스에 열린 모델 목록에서 고릅니다. AI 어시스턴트는 각 회사의 최상위 모델만 씁니다(FECINE v1.38.0).

::: tip TIP
좋은 요청에는 **목적 · 분량 · 톤 · 지켜야 할 것**이 들어갑니다.
예) “장면 2 대사를 더 짧고 어색하지 않게. 두 사람은 처음 만난 사이라 존댓말. 장면 순서와 등장인물은 바꾸지 말 것.”
:::

::: warning 주의
AI가 쓴 글은 **비교**에서 원래 글과 나란히 확인한 뒤 **장면에 적용**하세요. 적용한 뒤에도 **되돌리기**로 원래 글로 돌아갈 수 있습니다. 인물 이름, 장면 순서, 앞 장면과 이어지는 설정이 바뀌지 않았는지 꼭 봅니다.
:::

## PRACTICE — 요청문과 검토표

**실습 M1-1 요청문 쓰기**

장면 2(건네진 우산) 원고를 다듬는 요청문을 세 가지로 써 보고, 어느 것이 원하는 결과에 가까웠는지 비교합니다.

```text
① 다듬어 줘.
② 대사를 자연스럽게 다듬어 줘.
③ 장면 2 대사를 더 짧고 자연스럽게. 두 사람은 처음 만난 사이라 존댓말.
   도윤이 우산을 건네는 행동은 그대로 두고, 등장인물과 장면 순서는 바꾸지 말 것.
```

**실습 M1-2 AI 결과 검토표**

| 확인 항목 | 원래 원고 | AI 결과 | 맞음 / 고칠 것 |
| --- | --- | --- | --- |
| 등장인물 이름 | 수아, 도윤 | | |
| 장면 순서·행동 | 도윤이 우산을 건넴 | | |
| 말투 | 존댓말 | | |
| 분량 | | | |
| 새로 생긴 설정 | 없음 | | |

::: cost COST · 비용
텍스트 AI는 사용한 토큰만큼 크레딧이 듭니다. 이미지·영상보다는 적게 들지만, 긴 대본을 여러 번 다시 구성하면 비용이 쌓입니다. 요청을 구체적으로 써서 다시 받는 횟수를 줄이세요.
:::

## REVIEW — 제대로 했나요?

- [ ] 텍스트 AI가 매번 다른 글을 쓰는 이유를 설명할 수 있다.
- [ ] 토큰과 텍스트 요금 단위를 안다.
- [ ] FECINE에서 텍스트 AI가 쓰이는 곳을 다섯 가지 말할 수 있다.
- [ ] AI 결과를 비교한 뒤 적용했다.

| 상황 | 화면 문구 | 해결 |
| --- | --- | --- |
| 텍스트 모델을 고를 수 없음 | 지금 사용할 수 있는 텍스트 모델이 없습니다. | 관리자에게 워크스페이스의 텍스트 모델을 열어 달라고 요청 |
| 프롬프트 만들기 실패 | 프롬프트를 만들지 못했습니다. 잠시 후 다시 시도해 주세요. | 잠시 후 다시. 반복되면 원고 길이를 줄이기 |
| AI가 설정을 바꿈 | (결과 비교) | **버리기** 또는 **되돌리기**, 요청문에 “바꾸지 말 것”을 적기 |
| 원고가 없어 프롬프트를 못 만듦 | 이 장면에 원고가 없습니다. … | **스토리에서 원고 쓰기** |

**확인 문제**

1. 텍스트 AI가 사실이 아닌 내용을 그럴듯하게 쓰는 현상을 무엇이라고 하나요?
2. FECINE에서 텍스트 모델 요금은 어떤 단위로 표시되나요?
3. AI 어시스턴트의 제안은 자동으로 적용되나요?

정답: 1. 환각 2. 크레딧/100만 토큰 3. 아니다. 제안만 하고 적용은 사용자가 직접 누른다.

**응용 과제** 「비 오는 정류장」 장면 3 원고로 **원고로 프롬프트 만들기**를 실행하고, 만들어진 프롬프트와 25장에서 직접 쓴 프롬프트를 비교해 보세요.
