# 텍스트 생성 AI

<ChapterGoals />

## WHY — 영상 제작에 왜 글 쓰는 AI가 필요할까요?

> 영상 AI가 영상을 만드는데, 왜 텍스트 AI까지 알아야 하나요?

AI 영상의 품질은 **글**에서 시작합니다. 씬을 나누고, 씬 대본을 다듬고, 씬 대본을 영상용 프롬프트로 바꾸는 일을 텍스트 생성 AI가 돕습니다. 텍스트 AI가 어떻게 글을 만드는지 알면, 그럴듯하지만 틀린 글을 걸러 내고 더 좋은 요청을 쓸 수 있습니다.

- 텍스트 생성 AI가 글을 만드는 방식과 토큰을 설명한다.
- FECINE에서 텍스트 AI가 쓰이는 다섯 곳을 안다.
- AI가 쓴 글을 확인하고 적용하는 습관을 들인다.

**완성 결과물** 「비 오는 정류장」 텍스트 AI 요청문과 검토표

## HOW — 원리와 FECINE에서 쓰는 곳

### 다음 말을 이어 쓰는 기계

텍스트 생성 AI(대규모 언어 모델, LLM)는 많은 글을 학습해 **앞의 글 다음에 올 말을 확률로 골라 이어 쓰는** 방식으로 동작합니다. 그래서 다음과 같은 성질이 있습니다.

| 성질 | 뜻 | 실습에서 |
| --- | --- | --- |
| 매번 조금씩 다름 | 같은 요청에도 표현이 달라짐 | 마음에 들 때까지 다시 받되, 비교하고 고르기 |
| 그럴듯한 오류 | 사실이 아닌 내용을 자연스럽게 씀(환각) | 설정·이름·순서가 씬 대본과 맞는지 확인 |
| 요청에 민감 | 무엇을, 얼마나, 어떤 말투로 원하는지에 따라 결과가 달라짐 | 목적·분량·톤을 함께 적기 |
| 한 번에 읽는 양의 한도 | 너무 긴 글은 나누어 처리 | 긴 원문은 읽을 범위를 정하기(한 번에 최대 18,000자, [19장](/v1/chapters/19-ai-build)) |

### 토큰과 요금

텍스트 AI는 글을 **토큰**이라는 작은 조각으로 나누어 읽고 씁니다. 요금은 읽은 토큰(입력)과 쓴 토큰(출력)의 양으로 정해지며, FECINE의 요금표에서 텍스트 모델은 **크레딧/100만 토큰** 단위로 표시됩니다([13장](/v1/chapters/13-credits-and-cost), [부록 A](/v1/appendix/a-models-cost)). 같은 작업도 원문이 길수록, 만들 것이 많을수록 비용이 늘어납니다.

### FECINE에서 텍스트 AI가 쓰이는 곳

| 기능 | 하는 일 | 화면 | 장 |
| --- | --- | --- | --- |
| 씬 추가 · 씬 추출 | 씬 하나를 원하는 위치에 새로 쓰거나(`씬 추가`), 에피소드 줄거리로 씬을 나눠 제안함(`씬 추출`). 등장 요소가 있으면 씬에 연결 | **스토리 편집** › AI 어시스턴트의 요청 | [18](/v1/chapters/18-ai-writing) |
| 씬 요약 · 씬 대본 · 연출 노트 | 씬마다 `요약 만들기` · `대본 쓰기`/`대본 다듬기` · 연출 노트를 AI에게 요청(바라는 점을 `요청`에 적음) | **스토리 편집** › 씬 카드 · AI 어시스턴트 | 18 |
| AI 자동생성 | 작품 자료의 대본(대본 파일 또는 직접 쓴 스토리)을 읽어 에피소드·씬을 추출하고, 등장 요소 · 촬영 설계(콘티 · 샷 나누기)를 만듦. 어시스턴트가 대본 → 읽을 쪽 → 함께 만들 것 → 요청사항을 한 번에 하나씩 묻고, 진행은 `진행 상황` 탭에 쌓임. 이미지는 만들지 않음 | **스토리** › `작품 자료` · AI 어시스턴트 | [19](/v1/chapters/19-ai-build) |
| 씬 대본으로 프롬프트 만들기 | 씬 대본과 연출 노트를 영상 프롬프트와 권장 길이로 바꿈. 에피소드의 빈 씬을 한 번에 채우려면 `영상 프롬프트 만들기 · 빈 씬 {n}개` | 스토리보드 **프롬프트** 탭 | [25](/v1/chapters/25-camera-style) |
| AI 어시스턴트 | 지금 보는 등장인물·씬을 맥락으로 프롬프트를 함께 다듬음. 제안만 하고 적용은 직접 누름 | 작품 안 **AI 어시스턴트** | 18·25 |

텍스트 모델은 워크스페이스에 열린 모델 목록(`텍스트 모델`)에서 고릅니다. AI 어시스턴트도 이제 대표 모델 3개가 아니라 쓸 수 있는 텍스트 모델을 모두 고를 수 있고(`제공사`로 거름), 어시스턴트·작품 위키·씬 대본의 모델 선택이 같은 방식입니다. 텍스트 모델도 예상 크레딧이 낮은 순으로 보이며, 어시스턴트의 요청 흐름(단계별 질문)에서는 모델 선택 줄이 빠져 있고 설명은 ⓘ에 있습니다 <Badge type="warning" text="확인 필요" />.

::: info NOTE
FECINE의 모든 AI 요청은 **작품 위키**(작품정보 화면의 `작품 위키` 탭)를 먼저 읽습니다. 인물의 외모·말투, `프롬프트 규칙`, `연속성 메모`를 위키에 적어 두면 요청마다 되풀이하지 않아도 됩니다. 사람이 쓰거나 고친 항목은 잠겨서 AI가 바꾸지 않고 제안만 합니다.
:::

::: tip TIP
좋은 요청에는 **목적 · 분량 · 톤 · 지켜야 할 것**이 들어갑니다.
예) “씬 2 대사를 더 짧고 어색하지 않게. 두 사람은 처음 만난 사이라 존댓말. 씬 순서와 등장인물은 바꾸지 말 것.”
:::

::: warning 주의
AI가 쓴 글은 적용하기 전에 `지금 값`과 `제안`을 나란히 읽고, 마음에 들 때만 적용합니다('어시스턴트는 제안만 하고, 적용은 직접 눌러야 해요'). `씬 추가`·`등장 요소 만들기`처럼 작품에 바로 넣는 요청은 끝난 뒤 `진행 상황` 탭에서 결과를 확인하고, 필요 없으면 직접 고치거나 지웁니다 <Badge type="warning" text="확인 필요" />. 인물 이름, 씬 순서, 앞 씬과 이어지는 설정이 바뀌지 않았는지 꼭 봅니다.
:::

## PRACTICE — 요청문과 검토표

**실습 M1-1 요청문 쓰기**

씬 2(건네진 우산) 씬 대본을 다듬는 요청문을 세 가지로 써 보고, 어느 것이 원하는 결과에 가까웠는지 비교합니다.

```text
① 다듬어 줘.
② 대사를 자연스럽게 다듬어 줘.
③ 씬 2 대사를 더 짧고 자연스럽게. 두 사람은 처음 만난 사이라 존댓말.
   도윤이 우산을 건네는 행동은 그대로 두고, 등장인물과 씬 순서는 바꾸지 말 것.
```

**실습 M1-2 AI 결과 검토표**

| 확인 항목 | 원래 씬 대본 | AI 결과 | 맞음 / 고칠 것 |
| --- | --- | --- | --- |
| 등장인물 이름 | 수아, 도윤 | | |
| 씬 순서·행동 | 도윤이 우산을 건넴 | | |
| 말투 | 존댓말 | | |
| 분량 | | | |
| 새로 생긴 설정 | 없음 | | |

::: cost COST · 비용
텍스트 AI는 사용한 토큰만큼 크레딧이 듭니다. 이미지·영상보다는 적게 들지만, 긴 원문을 여러 번 다시 추출하면 비용이 쌓입니다. 요청을 구체적으로 써서 다시 받는 횟수를 줄이세요.
:::

## REVIEW — 제대로 했나요?

- [ ] 텍스트 AI가 매번 다른 글을 쓰는 이유를 설명할 수 있다.
- [ ] 토큰과 텍스트 요금 단위를 안다.
- [ ] FECINE에서 텍스트 AI가 쓰이는 곳을 다섯 가지 말할 수 있다.
- [ ] AI 결과를 비교한 뒤 적용했다.

| 상황 | 화면 문구 | 해결 |
| --- | --- | --- |
| 텍스트 모델을 고를 수 없음 | 지금 사용할 수 있는 텍스트 모델이 없습니다. | 관리자에게 워크스페이스의 텍스트 모델을 열어 달라고 요청 |
| 프롬프트 만들기 실패 | 프롬프트를 만들지 못했습니다. 잠시 후 다시 시도해 주세요. | 잠시 후 다시. 반복되면 씬 대본 길이를 줄이기 |
| AI가 설정을 바꿈 | (결과 비교) | 적용하지 않고 **취소**, 이미 넣은 글은 직접 고치기, 요청문에 “바꾸지 말 것”을 적기 |
| 씬 대본이 없어 프롬프트를 못 만듦 | 이 씬에 씬 대본이 없습니다. … | **스토리에서 씬 대본 쓰기** |
| 씬에 `수정됨` 표시 | 스토리에서 씬 구성이 바뀌었어요(합치기·나누기·옮기기). … | 새 씬 대본으로 **씬 대본으로 프롬프트 만들기**를 다시 실행 |

**확인 문제**

1. 텍스트 AI가 사실이 아닌 내용을 그럴듯하게 쓰는 현상을 무엇이라고 하나요?
2. FECINE에서 텍스트 모델 요금은 어떤 단위로 표시되나요?
3. AI 어시스턴트의 제안은 자동으로 적용되나요?

정답: 1. 환각 2. 크레딧/100만 토큰 3. 아니다. 제안만 하고 적용은 사용자가 직접 누른다.

**응용 과제** 「비 오는 정류장」 씬 3의 씬 대본으로 **씬 대본으로 프롬프트 만들기**를 실행하고, 만들어진 프롬프트와 25장에서 직접 쓴 프롬프트를 비교해 보세요.
