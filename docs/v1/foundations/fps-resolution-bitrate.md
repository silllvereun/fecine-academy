# FPS · 해상도 · 비트레이트

<ChapterGoals />

## WHY — 같은 영상인데 왜 파일마다 다르게 보일까요?

> 내 PC에서는 선명했는데, 휴대폰으로 보내니 흐릿하고 파일은 너무 큽니다. 무엇이 다른 걸까요?

영상 파일은 **1초에 몇 장을 보여 주는지(FPS)**, **한 장이 얼마나 촘촘한지(해상도)**, **1초에 데이터를 얼마나 쓰는지(비트레이트)**로 품질과 크기가 정해집니다. 이 세 값을 알면 AI로 만든 장면을 어디에 올리든 알맞은 파일로 내보낼 수 있습니다.

- FPS·해상도·비트레이트가 각각 무엇을 정하는지 설명한다.
- H.264 · H.265 · VP9 · ProRes 중 용도에 맞는 포맷을 고른다.
- 올릴 곳에 맞는 해상도·비율·포맷을 미리 정한다.

**완성 결과물** 「비 오는 정류장」 출력 사양표

## HOW — 세 가지 값과 코덱

### FPS: 1초에 보여 주는 장수

영상은 정지 그림(프레임)을 빠르게 넘겨 움직임처럼 보이게 합니다([3장](/v1/chapters/03-shot-cut-scene-sequence)). 1초에 넘기는 장수가 **FPS**(frames per second, 프레임 레이트)입니다.

| FPS | 느낌 | 주로 쓰는 곳 |
| --- | --- | --- |
| 24 | 영화 같은 움직임. 빠른 동작에는 잔상이 남음 | 영화, 드라마, 뮤직비디오 |
| 30 | 조금 더 매끄러움 | 웹 영상, 방송 |
| 60 | 아주 매끄러움. 영화 느낌은 줄어듦 | 게임, 스포츠, 화면 녹화 |

FPS가 높을수록 같은 길이에 프레임이 많아져 파일도 커집니다. 한 작품 안에서는 FPS를 하나로 맞추는 것이 원칙입니다.

처음에는 FPS를 따로 정할 필요가 없습니다. FECINE 편집은 원본 영상의 FPS(예: 24fps)를 그대로 따라갑니다.

### 해상도: 한 장의 촘촘함

**해상도**는 한 프레임의 가로×세로 점(픽셀) 수입니다. 흔히 세로 픽셀 수로 부릅니다.

| 이름 | 가로×세로 (16:9 기준) | 쓰임 |
| --- | --- | --- |
| 480p | 854×480 | 빠른 테스트, 미리보기 |
| 720p (HD) | 1280×720 | 웹·모바일 기본 |
| 1080p (Full HD) | 1920×1080 | 웹 고화질, 대부분의 납품 |
| 4K (UHD) | 3840×2160 | 대형 화면, 고화질 보관 |

**화면 비율**이 바뀌면 같은 이름이라도 가로·세로가 달라집니다. 9:16 세로 영상의 1080p는 1080×1920입니다.

::: warning 주의
작은 영상을 크게 늘리면(업스케일) 픽셀 수는 늘지만 없던 디테일이 생기지는 않습니다. 최종 해상도는 **만들 때** 정해집니다. 16:9로 만든 영상을 9:16으로 잘라 내면 가운데 일부만 남으므로 세로 해상도가 낮아집니다. 세로 영상이 주 목적이라면 작품을 처음부터 9:16으로 만드세요([16장](/v1/chapters/16-new-work)).
:::

### 비트레이트와 코덱: 1초에 쓰는 데이터

원본 프레임을 그대로 저장하면 파일이 너무 커서, 대부분의 영상은 **압축**해서 저장합니다. 압축하는 방식이 **코덱**, 1초 분량에 쓰는 데이터 양이 **비트레이트**(bps, 초당 비트)입니다.

- 비트레이트가 높으면 화질이 좋고 파일이 큽니다. 낮으면 움직임이 많은 장면(비, 물결, 연기)에서 뭉개짐(블록 노이즈)이 먼저 보입니다.
- 파일 크기는 대략 **비트레이트 × 길이**로 정해집니다.

비트레이트를 두 배로 올리면 파일도 약 두 배가 됩니다.

::: details 더 알아보기(선택): 파일 크기 계산
Mbps의 b는 ‘비트’, MB의 B는 ‘바이트’입니다. 8비트가 1바이트라서 8로 나눕니다.

```text
파일 크기(MB) ≈ 비트레이트(Mbps) × 길이(초) ÷ 8
예) 8 Mbps로 15초 → 8 × 15 ÷ 8 = 약 15 MB
```
:::

MP4·MOV·WebM은 파일 형식(파일 이름 끝의 확장자)이고, H.264·H.265·VP9·ProRes는 그 안에 영상을 눌러 담는 압축 방식(코덱)입니다. 처음에는 **MP4 / H.264**만 기억하면 됩니다.

| 포맷 / 코덱 | 특징 | 고르는 때 |
| --- | --- | --- |
| MP4 / H.264 | 거의 모든 기기·플랫폼에서 재생 | 기본값. 업로드·공유·보관 |
| MP4 / H.265 | 같은 화질에서 H.264보다 파일이 작음. 오래된 기기는 재생 못 할 수 있음 | 용량을 줄여야 할 때 |
| WebM / VP9 | 웹 브라우저용 공개 코덱 | 웹페이지에 직접 넣을 때 |
| MOV / ProRes 422 | 압축이 약해 화질 손실이 적고 파일이 매우 큼 | 다른 편집 프로그램·방송 단계로 넘길 때 |

### FECINE에서 하기

해상도와 비율은 세 곳에서 정해집니다.

1. **작품 설정** — 작품정보의 **설정 변경**에서 화면 비율과 해상도를 정합니다([16장](/v1/chapters/16-new-work)).
2. **씬 영상 생성** — 스토리보드 모델 탭의 **해상도**는 모델마다 고를 수 있는 값이 다릅니다([부록 A](/v1/appendix/a-models-cost)).
3. **내보내기** — **출력 프리셋**이 비율과 포맷을 정하고, 출력 탭에서 **포맷**과 **출력 크기**(편집본보다 큰 크기는 만들 수 없음, 최대 4K)를 고릅니다([30장](/v1/chapters/30-export-publish)).

::: tip TIP
FECINE 내보내기에는 비트레이트를 직접 정하는 칸이 없습니다. 포맷과 출력 크기로 품질과 파일 크기를 조절합니다. 파일이 너무 크면 H.265를 쓰거나 출력 크기를 한 단계 낮춰 보세요.
:::

| 비트레이트 | 계산 | 예상 크기 |
| --- | --- | --- |
| 4 Mbps | 4 × 15 ÷ 8 | |
| 8 Mbps | 8 × 15 ÷ 8 | |
| 16 Mbps | 16 × 15 ÷ 8 | |

**실습 F1-2 출력 사양표**

예제 작품은 16:9 · 720p로 만듭니다. 올릴 곳마다 사양을 정해 봅니다.

| 올릴 곳 | 비율 | 해상도 | 포맷 | FECINE 프리셋 |
| --- | --- | --- | --- | --- |
| 보관용 원본 | 16:9 | 720p (원본) | MP4 / H.264 | 마스터 |
| YouTube | | | | |
| Shorts · Reels | | | | |
| 다른 편집 프로그램으로 넘기기 | | | | (또는 편집 프로젝트 받기) |

::: cost COST · 비용
이 실습은 계산과 계획만 하므로 크레딧이 들지 않습니다. 해상도는 영상 생성 요금에 직접 영향을 주니, 테스트는 낮은 해상도로 하고 최종본만 올리세요([31장](/v1/chapters/31-saving-credits)).
:::

## REVIEW — 제대로 했나요?

- [ ] FPS·해상도·비트레이트가 각각 무엇을 정하는지 말할 수 있다.
- [ ] 파일 크기를 비트레이트와 길이로 어림할 수 있다.
- [ ] H.264와 ProRes를 언제 쓰는지 구분한다.
- [ ] 출력 사양표를 채웠다.

| 상황 | 화면 문구 | 해결 |
| --- | --- | --- |
| 원하는 해상도가 목록에 없음 | 선택한 모델이 지원하는 해상도와 길이를 다시 선택해 주세요. | 그 해상도를 지원하는 모델 고르기 (부록 A) |
| 출력 크기를 키울 수 없음 | 편집본보다 큰 크기는 만들 수 없습니다. | 작품·생성 단계에서 해상도를 정하기 |
| 포맷을 고를 수 없음 | 이 브라우저는 이 포맷으로 렌더할 수 없습니다. | MP4 / H.264를 쓰거나 최신 Chrome에서 열기 |
| ProRes 파일이 너무 큼 | ProRes는 파일이 매우 커서 이 크기로는 …분까지 만들 수 있습니다. | 출력 크기를 줄이거나 다른 포맷 고르기 |

**확인 문제**

1. 24fps와 60fps 중 영화 같은 느낌에 가까운 것은?
2. 10 Mbps로 30초 영상을 저장하면 대략 몇 MB인가요?
3. 거의 모든 기기에서 재생되는 포맷은 무엇인가요?

정답: 1. 24fps 2. 10 × 30 ÷ 8 ≈ 37.5 MB 3. MP4 / H.264

**응용 과제** 같은 편집본을 MP4 / H.264와 MP4 / H.265로 각각 내보내고, **렌더 이력**의 **크기**를 비교해 보세요. 내보내기를 두 번 하므로 내보내기 요금도 두 번 듭니다([부록 A](/v1/appendix/a-models-cost)).
